# Изменения внешнего API

## 2026-10-30 — VHSX_YuE2AutoInstrumental

Добавлена независимая нода `VHSX_YuE2AutoInstrumental`, отображаемое имя `YuE2 Auto Instrumental (VHSX)`.
Нода принимает ABC, режим исправления (`strict`, `safe`, `extended`), политику переноса мелодии,
режим Lyrics `sections_only`, `padding_seconds` (0–30, по умолчанию 0), `max_repair_units` (0–32,
по умолчанию 4 единицы `L:`) и `on_unrecoverable` (`error`, `smart` или `continue`; по умолчанию `error`).
`smart` принудительно использует `extended`; `continue` использует консервативный `safe` разбор.
В optional-входах есть `save_debug_artifacts` (по умолчанию `false`): при включении исходный ABC,
журнал исправлений и validation JSON сохраняются в уникальный каталог внутри output directory ComfyUI.
Для проверенного результата дополнительно сохраняются `repaired.abc` и `converted.abc`; для `PARTIAL_RAW`
сохраняется `partial_raw.abc`, без обозначения его как проверенного или преобразованного.
`max_repair_units` ограничивает только
эвристическое укорачивание Vocal при конфликте с последующей нотой; это не общий лимит восстановления.

По умолчанию используется `extended` и `instrumental_priority`: ноты Ins не меняют высоту, onset или
длительность, непересекающиеся части Vocal переносятся в Ins, а звучащие ноты Vocal заменяются паузами.
Расширенный режим лексирует ABC в токены, сохраняет частичный разбор, генерирует ограниченный набор
кандидатов исправления и проверяет результат повторным разбором. Переполненная нота может пройти через
границу такта с точными tie; при конфликте Vocal рассматривается перенос последующей последовательности.
Такой перенос помечается как эвристическое изменение временной шкалы. Переполнение Ins, которое нельзя
разрешить без изменения её нот, завершается диагностическим отказом.
Политика `vocal_priority` удаляет пересекающиеся части Ins; `mute_vocal_only` только заглушает Vocal.
Lyrics формируется из распознанных секционных комментариев; если их нет, выдаются `[intro]` и `[outro]`.
Chord symbols из обоих голосов сохраняются в Vocal. Лексически корректные, но неподдерживаемые качества
аккордов сохраняются без замены и отмечаются диагностикой с кодом `unsupported_chord_quality`.
Поддерживаются dotted-длительности, повторные варианты barline и chord labels на полном отдыхе `Z`;
нормализация repeat barline не воспроизводит повтор при проигрывании. Точная длительность может быть
разбита на поддерживаемые YuE единицы через ties. Результат сериализуется в согласованные группы Vocal/Ins
по 1–4 такта. Если короткий такт завершается tie, который пауза разорвала бы, нода отказывает в преобразовании.
Пустой или пробельный ABC возвращает пустые строки и нули со статусом `OK`.

Выходы: `abc`, `lyrics`, `max_duration`, `score_seconds`, `bars`, `bpm`, `info`, `warnings`, `repair_count`,
`conversion_status`.
`conversion_status` добавлен десятым выходом; первые девять сохраняют прежние позиции. Первые семь выходов
совместимы по типам с SBL. `score_seconds` учитывает смены темпа, `max_duration`
добавляет `padding_seconds` и округляется вверх. `warnings` содержит JSON с диагностиками и статистикой переноса.
Каждая диагностика имеет строковый `code`, а для неподдерживаемого качества аккорда он равен
`unsupported_chord_quality`. Статус `OK` означает, что внутренний валидатор принял результат;
`SMART_RECOVERED` означает, что режим `smart` применил восстановление и итоговая партитура прошла
внутреннюю проверку. В режиме `continue` принимаются только результаты без неоднозначных эвристических
изменений. Если восстановить score нельзя, `smart` и `continue` возвращают полный исходный текст со статусом
`PARTIAL_RAW`. Такой ABC сохраняется verbatim, но его валидность и отсутствие Vocal не подтверждены;
числовые выходы `0` являются sentinel неизвестного значения. `warnings` содержит статус, spans с исходными
смещениями/строками/текстом/причиной, сохранность источника, флаг Vocal, внутреннюю проверку и сведения о
незапущенном независимом checker. Статус `FAILED` записывается аудитом при отказе; в режиме `error` нода
по-прежнему выбрасывает исключение и не возвращает выходы. Независимый checker и YuE2 runtime не запускаются
нодой. Логика обработки доступна как обычная Python-функция `convert_abc` без запуска ComfyUI. Метрики корпуса,
синтетических повреждений и round-trip проверок приведены в
`doc/yue2_auto_instrumental_recovery_report.md`; постатейное сравнение с независимым YuE checker находится в
`doc/yue2_auto_instrumental_quality_report.md`.

## 2026-10-21 — VHSE_VideoSave

Добавлена независимая нода `VHSE_VideoSave`, название `Video Save Extended (VHS)`, категория `Video VHS Extended`.
Требуется установленный оригинальный VideoHelperSuite. Его файлы и регистрация нод не изменяются.

Нода принимает IMAGE, строковые `source_fps`, `target_fps`, `target_frames`, `width`, `height`,
параметры `resize_method`, `resize_mode`, `cq`, `preset`, `filename_prefix`, `save_output`.
Дополнительно можно передать AUDIO и `include_audio`.

По умолчанию сохраняется H.264 NVENC MP4, CQ 19, p5, bicubic center crop 1920×1080.
При выборе NVENC и его недоступности возвращается ошибка; автоматического переключения на CPU нет.

`target_frames` размещён в optional-входах, чтобы API мог опускать его. Пустая строка, `0`, `default`, `auto`,
`none` отключают retime. Без заданного положительного количества кадров нельзя менять FPS.
Положительное количество задаёт точное число кадров с сохранением первого и последнего исходных кадров.
При нескольких исходных кадрах запрос одного выходного отклоняется.

Пустые `width` и `height` сохраняют исходную геометрию с минимальным дополнением нечётных размеров справа/снизу.
Один пустой размер вычисляется из пропорций с округлением к ближайшему чётному, половины вверх.
Явно заданные размеры должны быть чётными, от 2 до 8192. Поддерживаются crop, pad, stretch.

Аудио необязательно; при отключении не добавляется. При retime высота тона сохраняется через atempo.
Конечный AAC 192k сводится копированием видеопотока. Длительность нормализуется без обрезки видео.

Возвращается `VHS_FILENAMES`: `(save_output, [путь_к_готовому_mp4])`, а также дескриптор preview в `ui.gifs`.
Перед публикацией проверяются кадры, FPS, CFR, разрешение, H.264/yuv420p, SAR, таймлайн и аудио.
Постоянный результат — один MP4; PNG с workflow не создаётся.
При несовместимом VHS или ошибке проверки операция завершается ошибкой с очисткой собственных временных файлов.

Пример API workflow: `examples/api_workflow.json`. Полное описание параметров: `README.md`.

## 2026-10-21 — CPU H.264 и подсказки

Добавлен optional-параметр `encoder`: `h264_nvenc` (по умолчанию) или `libx264` (CPU).
CPU-режим работает без NVIDIA и использует отдельный профиль `vhse_h264_cpu_crf-mp4.json`.
Поле `cq` в CPU-режиме передаётся как CRF, диапазон 0–51; CQ и CRF численно не эквивалентны.

Добавлен optional-параметр `cpu_preset`, по умолчанию `medium`:
`ultrafast`, `superfast`, `veryfast`, `faster`, `fast`, `medium`, `slow`, `slower`, `veryslow`.
Поле `preset` применяется только к NVIDIA, `cpu_preset` — только к CPU.
При ошибке NVIDIA автоматического переключения кодировщика нет; CPU выбирается явно.
Старые API workflow без новых параметров сохраняют поведение NVENC.

Для всех видимых полей GUI добавлены английские hover-подсказки, включая объяснения CQ/CRF и preset.

## 2026-10-21 — метаданные MP4

Добавлен optional-переключатель `save_metadata`, по умолчанию `true`.
В итоговый MP4 встраиваются переданные ComfyUI prompt, workflow и дополнительные поля `extra_pnginfo`.
Записываются JSON-теги MP4 и совместимый JSON-comment; результат проверяется перед публикацией файла.
При `false` эти поля не записываются. Для API workflow GUI-граф необходимо передать в `extra_pnginfo.workflow`.
Метаданные сохраняются как с аудио, так и без него, при CPU- и NVENC-кодировании.
Повторного кодирования видеопотока для метаданных нет.
