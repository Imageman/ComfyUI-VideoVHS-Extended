# История изменений

## 2026-10-30

Добавлена независимая библиотечная обработка YuE2 ABC и нода `VHSX_YuE2AutoInstrumental` с режимами
проверки/исправления, политикой приоритета Ins, Lyrics только из секционных тегов и структурированной диагностикой.
Пустой ABC сохраняет контракт no-op: пустые строковые и нулевые числовые выходы. Расширенное восстановление
сохраняет события через потерянные границы тактов, проверяет ограниченные кандидаты повторным разбором и
отклоняет конфликтующий Ins без изменения исходных нот. На обновлённом корпусе из 124 файлов новая нода
приняла 85, SBL — 33; неожиданных сбоев нет. На первых 96 файлах принято 63 против прежних 56. На добавленной
выборке 97–124 принято 22 из 28. Из 39 отказов 16 связаны с неподдержанными токенами, 12 с выравниванием
голосов, 8 с синтаксисом аккордов; остальные — единичные конфликты Ins, метаданных и структуры времени.
Синтетические случаи восстановлены точно 10/10, одна ожидаемая конфликтная запись безопасно отклонена.
Пройдены 31 проверка и корпусный прогон. Детали и ограничения: `doc/yue2_auto_instrumental_recovery_report.md`.
ComfyUI и YuE2 runtime недоступны для end-to-end проверки.

### Повторный аудит корпуса — 158 файлов

До исправлений повторно зафиксирована база: конвертер принимал 107/158, независимый YuE checker принимал
5 выходов. После исправлений конвертер принимает 103/158, внутренний разбор подтверждает все 103,
независимый YuE checker — 89/103. Сохранение Ins точно подтверждено для 43 исходно однозначных файлов;
для повреждённых входов отчёт отдельно отмечает неопределённость. Шесть прежних успехов теперь отклоняются,
когда короткий такт с завершающим tie нельзя безопасно дополнить паузой; два ранее отклонённых файла
восстанавливаются. Число снижено ради сохранения tie и временной шкалы, а не принято как цель само по себе.

Добавлены разбор музыки, приписанной к metadata field, проверка согласованных коротких тактов между голосами,
разделение лексически корректных и неподдерживаемых YuE chord qualities, безопасное разложение длительностей
на поддерживаемые единицы и каноническая сериализация в одинаковые группы Vocal/Ins по 1–4 такта.
Автоматическая подмена аккордов не выполняется. Проверки после исправлений: 31 unit-тест, синтетическое
восстановление 10/10, корпусная проверка 158 файлов и независимая upstream-валидация. Модель YuE2 и
аудиогенерация не запускались. Подробные результаты: `doc/yue2_auto_instrumental_recovery_report.md` и
`doc/yue2_auto_instrumental_quality_report.md`.

### Аудит по `sbl_fix4.md` — 329 файлов

Актуальный корпус содержит 329 файлов. До изменений зафиксированы 216 внутренних конвертаций, из них 198
приняты независимым checker; recovery — 59/96 development и 157/233 holdout, синтетика — 10/10.
После добавления `conversion_status` прогнаны все 329 файлов в трёх режимах. `error`: 216 внутренних
конвертаций, 198 приняты checker, 113 отказов конвертера. `smart`: те же 216 валидированных конвертаций;
для 113 отказов сохранён полный исходный ABC со статусом `PARTIAL_RAW`, одним span на файл и без подтверждения
отсутствия Vocal. `continue`: 91 валидированная конвертация (84 приняты checker), 238 `PARTIAL_RAW`;
консервативный режим дал на 125 меньше полностью валидированных результатов относительно `error`.

Во всех режимах обработано 329/329 файлов, audit errors — 0, SHA-256 источников совпал в 329/329.
Для всех 351 fallback spans проверены исходный текст и координаты полного диапазона; `partial_raw.abc`
побайтно соответствует декодированному исходному тексту. В этих результатах нет `repaired.abc`/`converted.abc`,
валидатор и отсутствие Vocal отмечены неподтверждёнными; неизвестные числовые значения — нулевые sentinel.
На файлах с доступным строгим raw-разбором note-события при восстановлении не удалялись и не менялись;
raw-to-repaired delta неизвестна для 240 файлов в `error`, 127 в `smart` и 3 в `continue`.
При конвертации `error`/`smart` перенесено 8992 Vocal-события, 33 не перенесены из-за конфликтов; в
`continue` перенесено 4440, одно не перенесено. Изменений исходных Ins-нот не зафиксировано.
После изменений прошли 41 unit/corpus тест, 3 quality теста и синтетическая recovery-проверка 10/10.
ComfyUI, YuE2 runtime и аудиогенерация не запускались. Полные пакеты:
`tmp/yue2_audit_fix4_verified/run_20261030_143436_001` (`error`),
`tmp/yue2_audit_fix4_verified/run_20261030_143436` (`smart`),
`tmp/yue2_audit_fix4_verified/run_20261030_143437` (`continue`).

### Аудит по `sbl_fix5.md` — 329 файлов

Реализован отдельный ограниченный smart beam search: проверяются гипотезы недостающего метра и границ
тактов, duration/tie и overfull-note исправления, повреждённые кавычки, объединённые metadata/music и
контекстная нормализация аккордов. Кандидат принимается только после полного строгого разбора и
сериализации; лимиты поиска — глубина 3, ширина 6, 32 попытки и 2 секунды на файл. Добавлен `SMART_PARTIAL`:
полный aligned-measure prefix конвертируется, неразобранные suffix spans сохраняются verbatim, статус
не считается полной конверсией, отсутствие Vocal не подтверждается.

До Fix5 `smart` совпадал с `error`: 216/329 внутренних конверсий и 198/329 приняты checker; 113 отказов
возвращались целиком как `PARTIAL_RAW`. После Fix5 `error` не изменился (216/329, 198 checker, 0 регрессий),
`smart` вырос до 246/329 полных внутренних конверсий и 228 checker (+30 без регрессий), ещё 74 результата
имеют статус `SMART_PARTIAL`, а raw-only осталось 9. `continue` повторил Fix4: 91/329 внутренних, 84 checker,
238 `PARTIAL_RAW`. Имена и исходные SHA-256 в baseline Fix4 и после Fix5 совпадают для всех 329/329 файлов.

Все 329 файлов проверены в каждом режиме; audit errors — 0. В 74 частичных результатах strict parser и
offline-checker приняли преобразованный фрагмент; 1546 verbatim-spans совпадают с исходными байтами и
не пересекаются. Учитывая сохранённые raw-фрагменты, Vocal absence для всех 74 результатов остаётся
неподтверждённым. Smart сохранил 40508 известных событий; 41 duration-гипотеза меняет ноту, удалённых
событий и изменений исходных Ins-нот нет. Событийный diff остаётся неизвестен у 157 повреждённых входов.

После итогового изменения прошли 48 unit/corpus тестов, 3 quality-теста и recovery evaluation: 59/96
development, 157/233 holdout, синтетика 10/10, неожиданных ошибок 0. Проверки независимы от ComfyUI и YuE2;
runtime и аудиогенерация не запускались. Отчёт и все per-file данные:
`doc/yue2_auto_instrumental_smart_report5.md`, `tmp/yue2_audit_fix5/run_20261030_151014` (`error`),
`tmp/yue2_audit_fix5/run_20261030_151102` (`smart`), `tmp/yue2_audit_fix5/run_20261030_151216`
(`continue`).

### Аудит по `sbl_fix6.md` — 329 файлов

Добавлены режимы Lyrics `sections_only`, `empty`, `instrumental_sections` и `instrumental_only`, синхронизация
секционных комментариев, mapping неизвестных названий в `Instrumental` и предупреждения для неоднозначных или
сгенерированных Lyrics. Tooltip режима исправления теперь описывает разницу между `strict`, `safe` и `extended`,
а также принудительный выбор `smart`/`continue`; fallback сохраняет best-effort длительность после полного safe-разбора,
а при полностью неизвестной длительности `max_duration` равен 300 секундам. Сериализатор сохраняет написание нот,
альтерации и ties, добавляя знак, только когда он нужен для точной высоты с учётом тональности и состояния такта.

До Fix6: 216/329 внутренних конверсий, 198 приняты checker; точные Ins pitch/time/ties и chord positions — по
89 однозначным файлам, точное написание Ins — 0/89. После Fix6 эти метрики сохранились, точное написание стало
89/89; ещё 240 повреждённых входов остаются неопределёнными. Во всех трёх режимах `error`, `smart`, `continue`
статусы совпали с Fix5 файл-в-файл, конверсионных регрессий нет. `error`: 216 полных конверсий, 198 приняты
checker; `smart`: 246 полных (228 приняты checker), 74 `SMART_PARTIAL`, 9 `PARTIAL_RAW`; `continue`: 91 полная
(84 приняты checker), 238 `PARTIAL_RAW`. SHA-256 всех 329 исходников совпал с baseline.

После Fix6 прошли 54 unit/corpus теста и 3 quality-теста; все три режима заново прогнаны на всём динамическом
корпусе, audit errors — 0. Результаты и per-file проверки: `doc/yue2_auto_instrumental_fix6_report.md`,
`doc/yue2_auto_instrumental_quality_fix6.md`,
`tmp/yue2_audit_fix6_final_duration300/run_20261030_155931` (`error`),
`tmp/yue2_audit_fix6_final_duration300/run_20261030_160020` (`smart`),
`tmp/yue2_audit_fix6_final_duration300/run_20261030_160142` (`continue`).
Для `PARTIAL_RAW` без измеримой длительности `max_duration` теперь равен 300 секундам, остальные
неизвестные числовые выходы — нулевые sentinel-ы. ComfyUI, YuE2 runtime и аудиогенерация не запускались.

## 2026-10-21

Реализована независимая нода `VHSE_VideoSave` — `Video Save Extended (VHS)`.
Добавлены делегирование кодирования оригинальному VHS, собственный NVENC-профиль, точное ленивое отображение
кадров, resize/crop/pad/stretch в FFmpeg, рациональный FPS, retime аудио через atempo и финальный mux без
повторного кодирования видео. Результат проверяется ffprobe и декодированием аудио до публикации.

Добавлены preview, README на английском, пример API workflow, русское описание API и тесты.
Локально: 80 passed, 2 skipped; отдельно прошли тест настоящих torch-тензоров и API-тест запущенной ComfyUI.
Проверены три длительных FullHD-прогона `tests/fly001.mp4` с аудио.

В реальной ComfyUI обнаружена и исправлена несовместимость tuple/list при подключении каталога форматов VHS.
Исходники и регистрация оригинального VHS не изменялись. Проверено его отдельное выполнение в том же workflow.
Подробности и ограничения: `VALIDATION.md`. Визуальная проверка preview и Linux/Docker/RunPod не выполнялись.

Добавлена возможность явного выбора CPU H.264 (`libx264`), отдельный `cpu_preset` и профиль CRF.
Параметр `cq` используется как CRF для CPU. Для всех полей GUI добавлены английские подсказки.
Новые параметры необязательны: существующие API workflow продолжают использовать NVENC.
Реальное CPU-кодирование проверено через оригинальный VHS с retime, resize, рациональным FPS и аудио;
отдельно проверено, что CPU-путь не вызывает проверку NVENC.

Добавлен включённый по умолчанию переключатель `save_metadata`: запись prompt, workflow и дополнительных
метаданных в итоговый MP4 с проверкой сохранённых тегов. Проверены CPU/NVENC, наличие/отсутствие аудио
и оба положения переключателя — 8 реальных тестов MP4 прошли.
В `examples/api_workflow.json` загрузка приведена к 24 FPS; source_fps и target_fps установлены в 24.

Исправлен сброс ширины ноды при загрузке preview после выполнения workflow.
Preview рассчитывается по текущей ширине ноды; автоподбор высоты сохраняет ширину и не уменьшает заданную высоту.
